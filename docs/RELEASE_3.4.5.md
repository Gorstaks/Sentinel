# Sentinel 3.4.5 — home/gaming endpoint protection

This release targets a standalone home/gaming PC, including a potentially targeted owner. Normal browsing, downloads, games, Discord/OBS streaming and user-initiated microphone/webcam use must coexist with protection. Another antivirus is optional. Tier1 means decisive supported behavior and responds immediately; it does not require a composite. Ambiguous evidence remains Tier2, never a destructive response.

## Runtime changes

- NanoAV's useful coverage is integrated into Sentinel scanning/reputation/rules. The archived autonomous engine is no longer launched or packaged. Upgrade retires only owned runtime/startup artifacts and preserves its quarantine/backups/database/logs. The confirmed unsigned-but-allowed → cached-bad deletion bug is not imported. See [exact scope](NANOAV.md).
- Register previously dormant raw socket-shell coverage. Require supported actual socket-to-shell command structures; echoed payload examples, ports, names and ordinary socket use do not suffice. Supported direct socket-shell containment cannot be suppressed by exhausting the global kill-count budget; other action budgets remain. It is fresh and process-lifetime pinned, durably audited, and does not trace/quarantine innocent ancestors or the backing image. Existing critical/self/game handle-safety limits remain; no kernel/driver protection is claimed.
- Online hash-only reputation in Service, with strict parsing, fixed TLS endpoints, budgets, freshness and Unknown fallback. Known-file reputation never grants process trust; cached reputation/static composite scores cannot authorize runtime kills. Exact current malware hashes have a separate bounded audited encrypted file-containment policy. No legacy verdict import, hard deletion fallback, ownership seizure or hash-based process kill.
- Remove broad folder-substring and globally spoofable servicing-process scan exemptions. Retain only actual OS servicing trees as omissions. Expanded script/native/macro coverage, PE-content recognition despite an unknown extension, Changed events, coalescing, four realtime workers, coverage-gap reconciliation on overload and cancellable draining. No scanner ADS writes/feedback loop; bound file-analysis/prevalence caches to 4,096 hashes and endpoint-timing history to 16,384 entries. A six-hour full re-evaluation runs after the prior walk completes; a slow/incomplete walk remains a limitation.
- Statistical connection timing alone is observation, not proof of C2. Games, launchers and messaging legitimately use periodic traffic. Keep separate decisive reverse-shell/other terminal rules; do not replace proof with reputation or trust scores.
- Privacy activity has managed group lifecycle and separate Tier2 categories. Unexpected overlays show high-priority review in the dashboard. Graphics module presence does not prove capture; Windows mic/camera records do not prove user intent or current process ownership. No typed text/audio/video is recorded by these changes. The privacy composite requires a verified overlay owner and independently proven socket shell in that same live lifetime; terminal response does not wait for it.
- Fix the remaining TLS monitor heuristic-removal bypass at producer and executor boundaries. Only explicit certificate distrust policy authorizes mutation; no inferred adder kill. Expiration, EKU or missing trust markers do not prove interception. Already-absent roots are distinguished from another actual removal. This does not reconstruct certificates removed by older versions.

## Network policy

Inbound-only image rules cover Service, Agent and Guard: Guard shares `Sentinel.Service.exe --watchdog`, so two rules cover three core processes. Retire old outbound self-blocks in PersistentStore and local GPO, recognizing both exact Name and COM DisplayName aliases. Preserve unrelated outbound policy, loopback and foreign collisions. This does not prevent local process injection.

The existing firewall reconciler manages default inbound Block and new/re-enabled unapproved inbound allow rules in both local stores; unique rule names do not establish approval. Explicit approvals remain tied to full filter identity. Effective/domain conflicts remain reported. The supplied Firewall.reg had 413 serialized rules and 19 enabled inbound allows; it is a registry snapshot, not effective-policy validation, and is not imported into the product.

A previously verified administrator-selected DNS profile can be reasserted automatically on an eligible unmanaged adapter, using the protected transaction, fresh fingerprints, audit, rollback and native read-back. Original rollback state survives reconciliation; restoration revokes that policy. No arbitrary first-seen DHCP/VPN configuration is overwritten.

Add bounded registry-integrity collection for real legacy IPsec, modern connection-security, DNS/NRPT and persistent-route policy. Existing compiled hosts/NRPT/browser policy remains active. Arbitrary /32 routes are no longer deleted based on shape or count. General autonomous route or arbitrary IPsec rewriting requires an approved target policy and is not implemented by this release. The historic `IPSecIntegrityGuard` maintains Windows Firewall port blocks, not an independent IPsec stack. Windows Firewall filters TCP/UDP/ICMP packets; IPsec is not independent of Windows/BFE. Registry readability is not verified IPsec negotiation/enforcement.

The owner's IPsec export contains repeated legacy policy sections and two ActivePolicy assignments; the last applicable assignment wins on import. The supplied script deletes/rebuilds a broadly scoped legacy port policy and can leave partial state after failure. Neither uploaded file is executed, imported, committed or used as a hidden universal baseline.

## Reviewed runtime evidence

The supplied 3.4.4 metrics show much faster startup and about 0.291% ETW dispatch drops, improved from prior evidence but still a collection gap. The file walk was incomplete, with protected/unreadable system files and approximately 2 GB working set. Bounded cache/realtime concurrency address identifiable growth risks; no measured target-host memory-leak resolution or complete scan is claimed. New target-host logs are still needed.

Five certificate response records represented three distinct thumbprints; absence read-back did not prove five new removals. Historical evidence packs are retained. STO crash/debug logs do not identify the faulting module or prove causation by NanoAV, Sentinel or MSI Afterburner.

## Validation boundaries

Pre-push product/shipping-test cross-build must have zero warnings/errors; portable regression, dashboard and fixed PowerShell policy tests must pass. See [red/blue audit](AUDIT_3.4.5.md). The Linux portable host explicitly skips native fixtures; that is not Windows validation. Build requires twelve native endpoint fixtures plus a separate disposable legacy-NanoAV migration smoke; release independently reruns shipping Windows tests and migration before publishing. Firewall native validation checks outbound/loopback availability and effective inbound policy. Public provider availability, live attacker benchmarking, interactive games/streaming, reboot/domain variants and the reported installation remain separate validation scopes. CI results belong to their exact commits.


The Agent's targeted overlay proof inspector queries only a reported unexpected overlay owner, through bounded local WMI metadata reads. It checks the same process lifetime before/after, requires supported socket-shell structure, and emits the privacy/terminal composite in Agent; Service/Agent telemetry is not assumed to share a correlation buffer. Ordinary Discord/OBS commands, input recipients, consultant signals and unavailable reads cannot promote the hint. At most two native reads remain in flight even after timeouts, and these reads do not block the terminal telemetry queue. No keyboard/media recording is added.


Final home-network review: remove blanket Sentinel-owned outbound game/client port blocks, retaining SMB/NetBIOS egress restrictions and inbound protection. Retire obsolete owned filters with group validation; preserve foreign collisions. Stop deleting legacy IPsec policies merely because they are named GSecurity. User-created legacy policies remain separate and may still affect connectivity. Hosting/LAN discovery can require explicit inbound approval; a game name alone cannot open an exception.
