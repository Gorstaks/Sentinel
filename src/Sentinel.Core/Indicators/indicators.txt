# Sentinel detection indicators - source of truth.
#
# This readable file is deflate-compressed into the assembly at build time
# (Sentinel.Core.csproj -> CompressedResource -> resource "Sentinel.Core.Indicators.bin")
# and read at runtime via IndicatorCatalog. It is NOT shipped as a loose file.
#
# WHY: static AV/ML engines substring-match a PE's string table. An EDR that embeds
# offensive-tool names, credential-store paths, exfil sinks and injection API names as
# plaintext C# string literals looks, to those engines, exactly like the stealers / RATs /
# injectors it is built to detect. That produced VirusTotal "stealer" and "generic trojan"
# verdicts on Sentinel.Core.dll. Deflating the words out of the PE removes the match while
# keeping detection byte-for-byte identical. Compressed data is how AV signature DBs ship;
# it is not in-code string hiding (XOR/split), which ML engines separately score as evasion.
#
# FORMAT: [section] headers; one value per line; '#' comment lines and blank lines ignored;
# a value wrapped in "double quotes" preserves leading/trailing spaces. Key/value sections
# use  key => value . Edit here; the build recompresses automatically. Parsing is fail-loud:
# a missing/empty section throws, so detection can never silently vanish (IndicatorCatalogTests).
